# Code, per-run records and derived data

Archive accompanying *Disentangling Graph Topology from Cross-Flow Context in Flow-Level
Intrusion Detection*.

Every number in the article and its supplement is produced from the files here. Nothing in
the article was typed in by hand: the tables are generated by the scripts in `code/` from
the records in `results/`.

## Layout

| Directory | Contents |
|---|---|
| `code/` | every experiment, analysis and figure script, plus `gnnlib.py`, the shared library holding the message-passing layers, the window construction and the training loop |
| `results/` | one JSON object per training run, written at run time, one file per experiment family |
| `tables/` | the generated LaTeX tables, and the JSON/CSV summaries they are built from |
| `figures/` | the figures of the article and the supplement |
| `metadata/` | dataset provenance, per-split class counts, removed-feature lists, checksums, software versions |

## Reproducing a result

1. Obtain the three public captures from their original distributors (see
   `metadata/` for the exact file lists and checksums used). They are **not** redistributed
   here: they are published under their own terms by the Canadian Institute for
   Cybersecurity (CIC-IoT2023, CIC-DDoS2019) and UNSW Canberra (UNSW-NB15).
2. Run `code/prep_ddos.py`, `code/prep_others.py` to build the prepared arrays. The
   preparation is deterministic given the released files and the seeds recorded in
   `metadata/`.
3. Run the experiment script named in the table or figure caption. Each appends one JSON
   record per run to the matching file in `results/`.
4. Run the matching `analyze_*.py` or `regen_*.py` script to rebuild the table.

## Files worth pointing out

- `results/holdout_prereg.json` — the prediction for the untouched holdout, with both
  purities and the direction expected, **recorded before any model was trained on those
  records**. The holdout is a stride of CIC-DDoS2019 disjoint from every record used
  anywhere else in the study; `code/prep_ddos_holdout.py` asserts the disjointness rather
  than assuming it.
- `code/exp_topology_control.py` — the matched-architecture topology control. One
  architecture, one parameter count, one edge count and one degree sequence; only which
  flows are linked changes.
- `code/exp_temporal_gnn.py` — the temporal and dynamic-graph baseline: temporal edges
  inside a window, and a per-host recurrent memory carried across windows, detached between
  windows and reset at every split boundary.
- `code/context_probe.py` — the generator for the controlled window-mixing environment, in
  which window purity is the only quantity that varies.

## What is deliberately absent

- The three public captures, for the licensing reason above.
- The prepared `.npz` arrays derived from them, for size; they are regenerated by the
  preparation scripts.
- No trained model weights are included. Every reported number is a mean over seeds and
  each run is reproducible from its seed.

## Limitation to be honest about

The container that produced this revision could not re-download the public captures, so the
two experiments added during revision — the matched-architecture topology control and the
temporal baseline — were run on the constructed probe environment rather than on
CIC-DDoS2019. The scripts take a `--dataset` argument and run unchanged on the prepared
arrays; that run is outstanding and is stated as outstanding in the article.
